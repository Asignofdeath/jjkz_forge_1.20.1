## 修复：跨维度后丢失术式（生得术式）

- 根因：服务端术式数据存在 `JjkzPlayerDataStorage`（挂在主世界的 SavedData，`server.overworld().getDataStorage()`），跨维度不受影响；丢的是**客户端**那份——`PlayerTechniqueData.applyClientTechnique` 把术式写进 `LocalPlayer.getPersistentData()`，而客户端在跨维度时收到 `ClientboundRespawnPacket` 会重建 `LocalPlayer`，PersistentData 随之清空。
- 原同步补全只覆盖 `PlayerLoggedInEvent` / `PlayerRespawnEvent` / `PlayerEvent.Clone`，缺跨维度场景。
- 修复：`CursedEnergyEvents` 新增 `onPlayerChangedDimension(PlayerChangedDimensionEvent)`，调用 `syncPlayerState` 并在下一 tick 再同步一次（避开客户端实体重建窗口期）。
- 已核实（Forge 1.20.x ServerPlayer.java.patch）：`changeDimension(ServerLevel, ITeleporter)` 与 `teleportTo(ServerLevel, ...)`（含 `TengenWedgeBarrierLogic` 用的 Set 版本）都会在末尾触发 `onPlayerChangedDimension`，事件覆盖全部跨维度路径。
- 注意：Forge 在 `copyFrom` 里只搬运 persistentData 的 `PlayerPersisted` 子标签，根级标签（如 `jujutsukaisenzone_innate_technique`）不会克隆，所以每次实体重建都必须靠服务端重新同步。
