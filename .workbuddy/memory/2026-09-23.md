## 星间飞行：跨序规则重写为「累积解锁位图」

用户定性：旧实现「当前实现无法按照顺序走完一趟」。先查证原作设定（Imai→Acrux→Mimosa→Ginan→Gacrux，

### 位图推导（已写进注释）

① 的初始位图 = {①②}；接触 ② → {①②③}；接触 ③ → {①②③④}；接触 ④ → 五颗齐。

### 与旧实现的差异（对应观察到的现象）

旧判据 `|ord(a) − ord(b)| >= 2` 的参照物是**两颗星各自的序号**，与「我走到哪一档」无关 → ① 走到 ③ 仍被判跨序，
一趟必然卡死。新判据是「对方那颗星在不在**我的位图**里」，位图会长 → 逐级放行。

## 编译错误修复：`StarArmorBreakEffect` 的 UUID 类型

用户贴来的 `compileJava` 报错：**唯一一个错误**是
`StarArmorBreakEffect.java:35: 不兼容的类型: UUID无法转换为String`（其余 8 条都是 `ResourceLocation`
`ItemBlockRenderTypes.setRenderLayer` 之类的 removal 警告，不阻断编译）。

根因：**1.20.1 的 `MobEffect#addAttributeModifier(Attribute, String uuid, double, Operation)` 第二个参数是
`String`**（原版内部自己 `UUID.fromString(...)`；只有更往后的版本才改成 ResourceLocation / Holder）。
之前手写时按习惯传了 `UUID` 对象 → 唯一候选方法参数不匹配。

修法（只动 1 个文件、2 处）：
- `private static final UUID ARMOR_MODIFIER_UUID = UUID.fromString("6f2b...")`
  → `private static final String ARMOR_MODIFIER_UUID = "6f2b..."`，并补注释写明「1.20.1 收 String」。
- 删掉随之无用的 `import java.util.UUID;`。

静态自查：全项目 `addAttributeModifier` / `ARMOR_MODIFIER_UUID` 各只有这一处（定义 + 唯一调用）；
`UUID` 在该文件已无任何引用（import 删除后不会留下 `UUID` 裸符号）；`AttributeModifier` import 仍被
`AttributeModifier.Operation.ADDITION` 使用，未误删。未跑 gradle（遵守禁令），编译结论等用户在 IDEA 里确认。

### 刻意的取舍

- **衰减只掉级、不消失**：用户此前为 `MARK_RANGE` 强调过「标记别自己跑掉」，所以标记生死仍由目标存亡决定。
- **解锁不因持续接触而续期**：只在窗口过期后重新授予 → 「碰一下」与「一直贴着」拿到等长窗口。贴着不动 ≈ 一直在经过；
  走完就散开则斥力自动恢复。**这一条直接消掉了聊了三轮的「走完顺序就永久破解」**。
- **杀生樱的「太近互相摧毁」没搬**：与同星吸引（`ATTRACT_RANGE=16`）、接触解锁（`CONTACT_RANGE=2.5`）、
  方块相邻 1 格三条现有规则正面冲突，会把刚成立的机制掐死。只搬了「数量上限」这一半。
- **杀生樱的「等阶随相邻数升阶」没搬**：星位等级是「叠次数」驱动，改成「相邻数」驱动会和叠加 / 引爆正面冲突。
- 传染照常走 `put` → 同样受上限约束，满员时顶掉最旧的几条，由 `Result.evicted()` 报到动作栏，不静默丢弃。

## 修「展开弹射零效果」（21:10，用户实测两次均无效）

用户实测：草方块+猪、自己+史莱姆，挨近开域**都没有弹开**。查出两个各自都能造成「完全零效果」的缺陷，
全部是我的实现错误：

1. **距离窗口有下限**（主因）：`if (distance <= CONTACT_RANGE || distance > BURST_RANGE)`。
   判的是**锚点**距离，而锚点比本体高（方块 +1.15，实体在头顶再 +0.45）。猪贴草方块旁 ≈ 1.5 格、
   站方块顶上 ≈ 1.2 格 → 全被 `<=2.5` 吃掉，一次 `push` 都没发生。用户「挨近」的摆位必然落进这一档。
   ⇒ 改为只判上界 `if (distance > BURST_RANGE)`；「是否排斥」本来就用位图判，与距离无关，去掉下限不会误弹相邻星。
2. **方向退化成纯垂直**：`dir` 取锚点差后 `multiply(1, REPULSION_VERTICAL_SCALE, 1)`。
   一方在另一方**正上方**（锚点水平重合）时方向是 (0,1,0)，乘 0.5 后水平分量**精确为 0**，
   表现成「原地蹦一下」。⇒ 新增 `burstKick(from, to, impulse)`：**只取水平分量**，水平重合时用
   `(impulse,0,0)` 兜底。

附带（可观测性）：`burstNeighbors` 改为返回弹开颗数，新增 `burstNote(int)` 把「；冲击弹开 N 颗」
拼进展开提示——**动作栏只有一个槽位**，单发一条会被紧随其后的展开提示覆盖，必须合并。

静态自查（未编译）：`burstNeighbors` 已改 `int` 且 2 个调用点都接 int；`burstNote` / `burstKick` /
`burstImpulse` 调用点齐全；`CONTACT_RANGE`(:734) 与 `REPULSION_VERTICAL_SCALE`(:775) 仍在常态逻辑里
被使用，没有沦为死常量；`BURST_RANGE` 的 Javadoc 已同步（原文「夹在 CONTACT_RANGE 与 REPULSION_RANGE 之间」
在新行为下已不成立）。

教训：① 判距离若不区分「锚点距离」与「本体距离」，窗口会整体错位一两格；② 一次性冲量的方向若走
「垂直缩放」而不做水平兜底，正上方摆位会静默变成零冲量；③ 看不到效果时，先让效果自己可计数
（并进已有提示），比反复口头描述强弱有用。

## 跨序解锁三道收口 + 弹射改「踢足球」（21:55）

用户实机反馈（Imai 自己 × Mimosa 猪）：开域被弹一下后照样贴上去，且「只碰了 Mimosa 却报解锁 Imai、Mimosa、Ginan」。
定位：① 提示把**两条标记**的新增位合成一句（Imai 是猪那边新增的、Ginan 是 Mimosa 的邻居白送）；
② 接触无条件授予 ⇒ 挤进去就跨级；③ 贴着目标会无限续期 ⇒ 一碰 = 永久。

**解锁侧改了三件事**（全在 `StarMarkRules`）

1. 提示分账：`int gainedMask` → `Map<StarMark,Integer> gains`（`LinkedHashMap`，由 `mergeUnlock` 写入），
   新增 `gainText(gains)`，输出形如 `★Imai 解锁 ★X、★Y ｜ ★Mimosa 解锁 ★Z`。
2. **接触收口**：接触的星必须**本来就在自己位图里**（即这一侧本来就不吃斥力）才 `mergeUnlock`，两侧各自判定。
   ⇒ 被排斥的星硬挤进去**什么都不发生**（Imai × Mimosa 从此不产生任何解锁）。
3. **一轮只授予一次**：`grantUnlock(expiry, contacted, initialMask, now)` 改判 `expiry[bit] != 0`（**含已过期**）
   ⇒ 过期不补发；初始位不记录。`hasActiveGrant` → `hasAnyGrant`（值 != 0），`flushUnlocks` 的保留条件是
   「曾经授予过」——**过期记录不能删**，删了下一 tick 会被当成「从未授予」重新补发。

**顺带修的死区**：接触分支原先无条件 `continue` ⇒ 距离 ≤ `CONTACT_RANGE` 的那一对**完全没有斥力**（最需要挡人的地方把力关了）。
现在只有「双方都算经过」时才自然跳过（pushA/pushB 都 false），否则照常推 —— 这正是「硬挤进去」也会被顶开的原因。

**弹射改「踢足球」**（用户原话：半径 8 也只是小幅度；况且弹开距离不变，星域尺寸只影响发射初速）

- 新增 `BURST_LIFT = 0.42`（**固定上抛**），`burstKick` = `水平投影.normalize()*初速 + (0, 0.42, 0)`。
  ⭐ 关键认识：**地面摩擦 45%/tick、空中只 9%/tick ⇒ 离地后同样初速多飞约 5 倍**；上抛取固定值 ⇒
  滞空时长一致 ⇒ 位移只由初速决定，正好符合「星域尺寸只影响初速」。1.4 约 9~10 格抛物线，0.6 约 4 格。
