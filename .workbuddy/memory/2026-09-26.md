## 第二轮：给暴击声明表加启动自检（推荐项 A-1 + C-7/C-8 注释兜底）

**自检本体**：`CritSkillPolicy.validate()`，在 `JuJutsuKaisenZone` 全部技能集注册之后调用（紧跟 `SeEffectRegistry.bootstrap()`）。
它只能读 `TechniqueSkillTreeRegistry.all()` —— 技能树是在 `TechniqueSkillSetRegistry.register(...)` 内部才注册进去的，
所以**调用时机不能提前**（提前会命中「技能表为空」的守卫而抛异常）。查四件事：

1. 两份名单都不许为空（清空等于把标注关掉，应是有意改动）。
2. 技能表此刻不能为空（= 时机不对，提前调用了）。
3. `NO_CRIT_SKILLS` 每个 id 必须存在于已注册技能表（技能节点 skillId ∪ `CommonTechniqueSkillRegistry.getConfigurableSkills()`）。
   拼错/改名漏改 ⇒ **标注永远不出现**，界面上只是少一行字、没有任何报错。
4. `NO_CRIT_INFO_NODES` 每个 nodeId 必须是**领域**说明节点。

抛 `IllegalStateException`，与 `TechniqueSkillTree#validate` / `validateAgainstSkills` 同一风格。

## 更正：领域展开是技能树里的**说明节点**，不是「没有节点」

用户纠正：领域在技能树里是**说明节点**（`SkillTreeNodeDef.info(...)`，靠 `visibleWhen(UnlockCondition.hasDomainExpansion())` 控制显隐），
它的悬停框在 `SkillTreeNodeWidget#refreshHoverTooltips` 的 `isInfoNode()` 分支里手搓（不走 `TechniqueSkillTooltipHelper`），
已带一行红色「领域展开」标注（`DOMAIN_EXPANSION_TAG`）。我先前说「领域没有节点/没有描述标注」是错的。

- 领域**没有 skillId**（不是可释放技能），所以标注只能按 `nodeId` 定位。
- 四个领域里只有「伏魔神龛」（御厨子）直接出伤，且是 `tickShrineSlashDamage` 每 10 tick 的持续伤害 ⇒ 属高频。
  （`grep TechniqueDamageSources|hurt` 扫过整个 `technique/domain/` 包，只有 `ShrineDomainExpansion:1296,1315`。）
- 落地：`ShrineTechniqueSkillSet.INFO_DOMAIN_FUMOSHINKAN` 常量化 nodeId（树里也改用它）⇒ `CritSkillPolicy.NO_CRIT_INFO_NODES`
  收 `ShrineTechniqueSkillSet.INFO_DOMAIN_FUMOSHINKAN`，`CritSkillPolicy#isNoCritInfoNode(nodeId)` 供悬停框判断，
  `SkillTreeNodeWidget` 该分支改成先拼 `List<Component>` 再 `setHoverTooltips(list)`（标注行位置：标题下、正文上，浅紫）。
- ⚠️ 顺带一个泛化教训：**「某机制在技能树里有没有节点」要先 grep `SkillTreeNodeDef.info(` / `isInfoNode` 再下结论**，
  别从「它不是可释放技能」倒推「它没有节点」——技能树里有 INFO / REFERENCE / SPECIAL_MOVE / SKILL 四种节点。
